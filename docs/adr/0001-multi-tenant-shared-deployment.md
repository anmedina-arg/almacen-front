# Multi-tenant como base compartida, no clones por cliente

Al recibir un segundo cliente para el producto, se evaluó clonar el repo/infraestructura por cada Store versus construir el concepto de Store en el modelo de datos actual (single-tenant, sin `store_id` en ninguna tabla, admin global). Se optó por construir la base multi-tenant ahora, con un único deployment compartido para todas las Stores, en lugar de clonar. Con solo un tenant real hoy (Market Cevil), es el momento más barato para migrar — clonar primero y unificar después, con clones ya en producción y con datos reales, sería considerablemente más caro y riesgoso. El plan de largo plazo es vender esto como SaaS a múltiples comercios con un panel de admin cada vez más robusto, lo que exige una base unificada de todos modos.
